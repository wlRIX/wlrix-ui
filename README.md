# wlrix-ui

The drawing primitives and the color palette shared by wlRIX's Rust components.

`wlrix-compositor` draws window frames, menus and minimized-window tiles. `wlrix-greeter`
draws a Motif login dialog. `wlrix-desktop` draws icons and a menu. All three draw the same IRIX chrome, and until this
crate existed all three had their own copy of it — copied by hand, annotated as copied, and quietly diverging.
`_docs/case-for-ui.md` set the condition for pulling them out: a third consumer. This is that.

It is a library. It installs nothing and has no `just install`.

## What is in it

| Module    |                                                                         |
|-----------|-------------------------------------------------------------------------|
| `color`   | `Rgb`, packed native-endian ARGB                                        |
| `canvas`  | `Canvas`, a borrowed `wl_shm` `Argb8888` surface, and `Rect`            |
| `bevel`   | Motif bevel geometry with no opinion about where the pixels go          |
| `motif`   | the canvas sink for that geometry: `panel`, `draw`, `outline`, `groove` |
| `widget`  | `button`, `text_field`, `arrow`                                         |
| `text`    | one cosmic-text setup: shaping, metrics, wrapping, and two output sinks |
| `mask`    | an 8-bit coverage bitmap, for artwork tinted by its state               |
| `image`   | SVG and PNG decoded to premultiplied `Argb8888` (feature `image`)       |
| `palette` | the generated color schemes                                             |

Layout, hit-testing and event handling are deliberately absent. They are what each component *is*, and a shared widget
that owned them would have to know about three different event loops.

## Features

`text` is on by default. `image` is off — only `wlrix-desktop` loads image files, and
`resvg` is a large dependency for a component that never calls it.

There is **no smithay feature, deliberately.** The compositor needs `Color32F`, which is a
`[f32; 4]` newtype with a `From` impl, so `Rgb::to_f32_array()` is the whole interop surface. Depending on smithay would
pin this crate to the same git rev `wlrix-compositor` pins, and make every smithay bump a two-repo lockstep — for the
greeter and the desktop too, which have no business knowing smithay exists.

## The palette

`src/palette/generated.rs` is generated by `wlrix-assets/tools/palettegen` from the JSON in
`wlrix-assets/palette/`, the same source the Avalonia theme's scheme dictionaries come from. **Never edit it.** Edit the
JSON and run `just palette` from `wlrix-epoch`; `just
check-palette` fails if the checked-in file is stale.

A `Palette` is a value, not a wall of constants. It used to be three walls: thirteen `const`s for the compositor in
`Color32F`, twenty-three for the greeter and twelve for the desktop in a packed `u32`, each list hand-picked in the
generator. Nothing could change palette while running, one color had three names, and the window chrome — the most
visible surface in the desktop — was bound to none of them and carried eight literals of its own.

Two schemes ship: **Classic** (Indigo Magic, IRIX's default) in three gamma bakes, and **Gotham**, IRIX's dark scheme.

```rust
let (palette, unknown) = wlrix_ui::palette::resolve(config.palette.as_deref());
if let Some(why) = unknown {
eprintln!("wlrix-thing: {why}; using {}", palette.id);
}
```

`resolve` falls back to `DEFAULT` and hands back the reason rather than printing in a voice it does not own. A mistyped
scheme name must not leave someone staring at a black screen.

## Developing against a checkout

Consumers depend on this by git rev, so a fresh clone of any of them builds standalone. While working on both sides at
once, `just link-ui` in `wlrix-epoch` writes a `[patch]` into each consumer's `.cargo/config.toml` pointing at the
sibling clone; `just unlink-ui` removes it.
`just bump-ui` moves every consumer's pinned rev to this repo's `HEAD`.

## Testing

```
just test
```

51 tests, no display and no compositor needed — which is most of the point. The bevel rule, the wrapping, the blend
arithmetic and the palette values are all testable without a screen for the first time.
